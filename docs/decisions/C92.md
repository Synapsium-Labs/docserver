# C92: Task 11's and Task 7's rulings

*Recorded 2026-10-27, coordinator.* · [Decision log](README.md)

## Decision

Task 11: (1) its two hostile cases, `h-dom-clobber-frame-names` and `h-xml-script-style-256k`, are additions named in the commit's `Goldens-moved:` trailer, which the ratchet requires for any expected file that changes; no existing golden moves. (2) The xml case is committed as a corpus file (about 530 KB ships) because the generated-input budget is nearly full; the budget is not raised. (3) `src/highlight` stays out of the package build until Task 12 exports `./highlight`, as `src/host` does, pinned by a package row; its emitted declarations import no highlight.js type, so a worker consumer loads no DOM declarations. (4) The README's hostile count (17) and the `highlight` render option go to Task 12, which owns the README. Task 7: (5) the Mermaid gate follows the first consumer's spec §4.6 and M8.20: `inline` reads the fence count and the total, and the per-fence cap travels to the layout as `maxTextSize`, so only an over-long fence shows as source. (6) The conformance frame mutants are templates whose policy and asset text are placeholders filled from a fresh build; full srcdocs would carry about 4.5 MB of assets each and move with every rebuild, and `clean.html` is checked against a fresh `frameDocument`. Each mutant is judged by its own row's check, and Task 12's smoke does the same. (7) `seed-raw-line-separators.html` holds raw U+2028 and U+2029 because that is the defect it carries; it is the one named exception to R6. (8) `MAX_SRCDOC_CHARS_DEFAULT` adds a skeleton term, derived from the template pieces `frameDocument` writes and the policy floor's maximum policy length, so FD17's "no legal document refused by the default" holds to the character; the default is about 114.6 million characters, which widens risk R1 as [C87](C87.md) said. (9) Accepted deviations: byte rules run before the hash check, so a planted CR, NUL or `</script` reports `unsafe-asset`; two hostile cases that do not render are refused `not-rendered`; two plan mutations are planted where the build still runs. Task 7's verify line gains `test/frame-pure.test.ts`.

## Why

Each is the reading of the plan and the consumer's spec that the measured code meets.

## Cost if wrong

The gate reading changes one condition and one assertion; a skeleton change that the term did not follow would make a maximal document `too-large`, which the term's test catches.
