# C65: Attention may complete its pre-fold joins synchronously at the settings boundary

*Recorded 2026-10-21, coordinator.* · [Decision log](README.md)

## Decision

This is a bounded internal correction for Product controls built before the folds facade is installed, not a new readiness protocol or task acceptance.
- **Exact source scope:** `src/enhance/attention.ts` owns one lazy context-keyed state and the internal export `completeFoldJoins(ctx: FeatureContext): void`. Register state before initial Product control creation; retain every exact precompletion bar/target/source pair, including explicit or stored Product and Product selected reentrantly by the folds getter. Keep the existing one-time construction flag separate from completion. A prebuild join returning false is not readiness and does not remove the retained pair.
- **Persistent completion:** look up the context before accessing its methods; unknown or non-live contexts do nothing. Mark completion and detach the pending cohort before any joins, making reentry and repeated calls harmless. Complete even with an empty cohort or disabled/empty folds, independently of the current lens. A first Product choice after completion joins immediately through the same validation, without another pending queue. Journal cleanup deletes the registry entry and releases retained pairs; import remains inert.
- **Exact associations only:** before every join, recheck liveness, the original bar as direct-root-child chrome, the original target as a direct root child, and the original registered source still equal to or contained in that exact target. The filtered table retains its inner renderer identity within its outer presentation target. Removed, replaced, nested or other-root identities receive no join; do not find substitutes, rescan author blocks, retarget or impose a new adjacency contract. Folds alone decides whether the exact target still belongs to a valid section. A false join is not permission to enroll or replay; destroy stops further calls. Completion faults propagate through existing startup rollback; faults from later immediate joins retain existing event/operation propagation, with no new rollback.
- **One synchronous call:** `src/enhance/settings.ts` imports the helper and calls it as the first statement of `build`, before both optional settings/slots guards. Existing feature order therefore completes after folds and before position, inside startup rollback. No `attention.after`, asynchronous phase, reservations, half-ready facade, lifecycle edit or public/context/Folds interface change is authorized. Existing lens ownership, filtered-table behavior and preference/control semantics remain unchanged.
- **Dedicated permanent controls:** new `test/enhance-attention-folds.test.ts` and `test/browser/attention-folds.test.ts` own this correction; existing tests stay readonly. Genuine reds precede edits for explicit/stored/getter-reentrant Product fold membership, including a switch back to Everything. Cover empty completion then first Product, settings-disabled/no-slot roots, disabled/empty folds, exact stale-pair rejection beside a surviving valid pair, sibling isolation, idempotent reentry, destroy and exception rollback. Nonempty-drain reentry and later first construction are separate cases; do not reset the one-time flag or build attention twice. Independently reverse completion, guard placement, initial retention, empty/current-lens behavior, reentry ordering, exact identity validation and cleanup; report real assertion reds and restores, including any survivor. Require both browsers with shipped CSS/strict CSP and actual fold interactions, existing table/settings/fold/lifecycle controls, all TypeScript projects, unchanged walls/import controls and a stable full named-failure census.
- Source implementation requires a separate explicit release on stable corrected peer inputs; it must not overlap the current menu or fold/relayout/rail writer. All other production files, feature order, source capture/reading arithmetic, environment, journal, CSS, harness/configuration, scanners, corpus, goldens, RF3/navigation/geometry limits and required-model gates remain unchanged. This records no Task 18/19 or combined-group acceptance.

## Why

Early Product bars currently attempt an empty prebuild facade and never retry, while a later Product choice already joins.

## Cost if wrong

A late or repeated completion can miss stored folds, enroll stale identities or escape startup rollback; the single synchronous boundary, held identities and lifecycle controls bound that correction.
