# C98: Task 12's rulings

*Recorded 2026-10-28, coordinator.* · [Decision log](README.md)

## Decision

(1) Release verification is five commands, not four: `npm install … --ignore-scripts`, `npm audit signatures`, `npm pack @synapsium-labs/docserver@$VERSION` (the registry's own bytes, under the name the next two commands read), a `test` that the registry's `dist.integrity` equals that tarball's sha512, and `gh attestation verify`. As the plan wrote them, nothing fetched the tarball the last command reads and nothing compared the integrity. The plan's Reference §13 step 7, L3.W9 and Task 15 step 9 are amended to match, and release.yml's post-verify runs the README's lines verbatim. (2) The srcdoc scans move verbatim into `scripts/frame-scans.mjs` (with its `.d.mts`), and `test/frame-scans.ts` re-exports them, so the consumer smoke, a plain `.mjs`, runs the very scans the tests run, not a copy. They read parse5 from the checkout's dependency tree, where it arrives through jsdom and is pinned by the lockfile. (3) "The M8.3 and M8.4 scans fail on every frame mutant" cannot hold as written: `seed-raw-line-separators.html` passes both by design ([C92](C92.md)(7)). The smoke judges each mutant by its own row's scan, as the shipped `index.json` says, and runs M8.8 as well. (4) Accepted: `src/conformance/bridge.ts` for `bridgeCases()`, and `test/pack.test.ts`'s allowed list widened only by the newly shipped paths, with the pack row pinning 13 assets and 16 mutants; a defective-tarball row in the pack project keeps every failure branch of the smoke measurable; import-inertness is judged per entry, each imported alone in a fresh process with the traps set before any module of the package loads. (5) The README states the bridge's flat-object rule for the frame's messages only; of the parent's, `changes.result` carries `ranges` (a list of integer pairs), `removedAfter` (a list of integers) or `unavailable: true`, which the shipped fixtures accept. (6) The host duty of [C94](C94.md)(3) is narrowed and measured: a page policy that admits only the stylesheet's hash serves documents with neither Mermaid nor an aligned table, because an aligned cell carries its alignment in a `style` attribute that no stylesheet hash admits. A row on both engines in `test/browser/mermaid-on-request.test.ts`, outside the task's file list, holds that such a document fails closed and is never partly working. (7) Task 10's drafted claim that a host may list URL sources beside the four hashes is dropped, because nothing measures it. (8) The README quotes `frameCsp()` whole, so any rebuild of the frame's assets (Task 13 included) updates that quotation in the same change; the readme test stays red until it does.

## Why

Each keeps the README runnable and true against the shipped code.

## Cost if wrong

A reader follows a narrower rule than the code allows, which is the safe direction.
