# C95: Task 8's rulings

*Recorded 2026-10-28, coordinator.* · [Decision log](README.md)

## Decision

(1) L3.B14 is red as the plan defines it. With the page clock fixed so the anchored drawing gets the anchored ids, all 14 cases are damaged: the anchor that carries the drawing's name takes the drawing, Mermaid's cleanup removes an authored anchor in place of its own working element, and 8 marker or gradient references resolve to authored anchors. The damage stays in the frame: no violation, no request, no second load. The plan's contingency applies, so the id prefix ships in Task 8's PR. Mermaid 12.1.0's `run()` names each drawing `mermaid-<Date.now()>` and takes no id, so the reader draws through Mermaid's `render(id, text, container)` with a reader-issued id. Its prefix holds a code point that the library's `render()` can never emit in an id (the anchor grammar `[A-Za-z0-9_-]`, the slug alphabet, and every other id it writes), and that every engine accepts unescaped in a CSS selector, since Mermaid writes the id into selectors and its stylesheet. The reader prepares the text as `run()` does, inserts the returned SVG through an inert `DOMParser` parse (never `innerHTML`), and calls the returned `bindFunctions` as `run()` would. The prefix is a guard with its own mutation row (drop the prefix: L3.B14 red); the `it.fails` row becomes a plain row; a moved Level 2 case is named in a `Layout-moved:` trailer. Rejected: (b) renaming the drawing's ids after it draws, because the collision happens during the draw; (c) refusing `[di]?mermaid-<digits>` ids in `render()`, because it narrows the authoring and slug contract of every document to work around one dependency's naming; `deterministicIds`, because it names drawings `mermaid-0`, which any document can author. (2) L3.B3p-b ("pin only absent names") is not yet an equivalent mutant. Its planted reader read `addEventListener`, which an engine keeps as an own property of the window (a global interface's inherited operations live on the instance), so no id could shadow it. Names the window inherits from `Object.prototype` (`valueOf`, `toString`, `hasOwnProperty` and the rest) sit behind the window's named properties object, which an id does shadow, and the anchor grammar can author them. The row is measured again with a planted reader of one of those names: red, it counts; still green, it is recorded as an equivalent measured on Chromium, with WebKit unmeasured. (3) Accepted: the shared helper module `test/browser/frame-shared.ts`, because a test file cannot export helpers without registering its tests; P1, P2 and the measurement rows moved into `frame-csp` and `frame-measure`, where the plan's "From the prototype" places them; the load-tolerant progress wait with its control row (it gives up after 20 s with no progress the parent can see, allows a busy frame up to 60 s more, caps each document at 180 s, never retries), and L3.B10's 540 s budget, which names every document it gave up on or never reached; the 11 extra diagram kinds that L3.B3p and L3.B14 draw beyond the corpus; L3.B2's mutant going red through the refusal before any request is made, with the new L3.B2 control showing that the request log hears a frame's request; L3.B15's limit row split into two rows; and the stricter L3.B13 IndexedDB check (only a throw or a refusal passes) with its control. If WebKit's opaque-origin frame opens an IndexedDB, that is a finding for the coordinator, never a reason to relax the check.

## Why

The plan names the prefix as the answer to a red L3.B14, and drawing under a reader-issued id is the only option that prevents the collision rather than repairing it afterwards.

## Cost if wrong

The drawing path changes for every reader, which the diagram units, the Level 2 goldens and both engines in CI cover.
