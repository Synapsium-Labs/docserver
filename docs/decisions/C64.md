# C64: A scrim close may restore focus from its exact reader root

*Recorded 2026-10-21, coordinator.* · [Decision log](README.md)

## Decision

This is a bounded Task 18 source correction to the physical-input failure exposed by [C61](C61.md), not general root-focus eligibility or task acceptance.
- **Sole source scope:** the private `focusBack` and `close` functions in `src/enhance/rail.ts` take a default-false boolean permission. `close` passes it to `focusBack`; the scrim listener alone supplies literal `true` through `() => close(true)`. Eligibility adds only `fromScrim === true && focused === root` to the existing exact-body-or-rail rule. Keep the structural first-XHTML-body/frameset predicate, opener then Contents then root fallback, `preventScroll`, close mutation order, conditional root-tabindex ownership and deferred cleanup unchanged. Do not use root containment, a stored permission, focus snapshots, mousedown prevention or asynchronous restoration.
- **Every ordinary close keeps the default.** Contents toggle, resolved plain links, rail Escape, shared keyboard/overlay close and deferred destroy call with no permission. The actual overlay and journal invoke their close callbacks with zero arguments; the event listener must use its explicit wrapper rather than passing an Event into the boolean parameter. There is no current viewport-close callback, and this correction adds none. Cleanup retains its existing permission to restore focus while non-live; this is not a new forward-work exception.
- **Bounded consequence:** native scrim input can focus a focusable ancestor root before click, with either library-added tabindex minus one or host-preexisting zero. The permission is scoped to that scrim close and exact identity, not proof of physical input or host intent: a synthetic scrim click with the root focused also qualifies, and intentionally focusing that same root cannot be distinguished here. Host controls within the root but outside the rail, other readers and outside controls gain no eligibility. No permission survives into later closes.
- **Dedicated permanent tests:** new `test/enhance-rail-scrim.test.ts` and `test/browser/rail-scrim.test.ts` own this correction; existing shared tests stay readonly. Establish genuine assertion reds before source edits for the connected-opener case and both absent/preexisting-zero tabindex shapes. Browser cases use the actual stylesheet and strict CSP at 390 px, prove rail focus and a visible point outside the drawer with exact scrim hit identity, then use real mouse input. Require closed modal/expanded/hidden states, restored opener, unchanged scroll and conditional tabindex teardown. Do not force body focus, remove the temporary tabindex, synthesize the physical click or weaken [C61](C61.md)'s original assertions.
- **Negative and lifecycle controls:** exact-root focus does not authorize ordinary Escape, toggle, overlay or destroy restoration; non-root host focus survives scrim close, including click-capture focus changes. Cover non-sticky permission, repeated closed clicks, disconnected fallback targets and reentrant destroy before the listener or during opener focus. Delete the new branch, remove its scrim restriction and broaden identity to containment independently; the corresponding positive and negative behavioral assertions must fail, then restore green. Retain the exact-body semantic mutants and existing focus, Index, status and ordering controls; run both engines, all TypeScript projects, unchanged walls and a stable full named-failure census.
- Release no rail writer concurrently with the current fold or relayout writer. All lifecycle, journal, overlay interfaces, environment, CSS, harness, configuration, scanners, corpus, goldens, navigation and RF3/geometry limits remain unchanged. This grants no attention completion export, required-model waiver, Task 18/19 or combined-group acceptance.

## Why

Both browsers identify the exact root after native scrim input, so the existing body-or-rail guard refuses the connected opener.

## Cost if wrong

Admitting root focus too broadly steals a host's focus; the stack-local permission and ordinary-close/host-control negatives bound that exception.
