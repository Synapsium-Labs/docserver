# C108: Item C, one header bar for a host that has its own

*Recorded 2026-11-05, coordinator.* · [Decision log](README.md)

## Decision

The plan's CD1 to CD9 stand as built. (1) CD1 to CD9: `chrome.bar: false` is the existing switch; the reading settings button (Aa) is built without the bar, at the root's top right, and `chrome.settings: false` opts out; one parent-to-frame op `command` with the names `jump`, `settings`, `contents` and `outline` (Q7), each a toggle, the names held equal in `./enhance` and `./frame`; `DocFrame.command(name)` drops before `ready`, throws on an unknown name and focuses the iframe first; `progress` is a frame-to-parent op carrying thousandths as a string, sent only when the seed's `bridge.progress` is true, which defaults to false in `frameDocument` and which `./host` sets only when `onProgress` is given; progress is coalesced to at most 4 a second in 250 ms windows (Q15); no title op (Q9); `--bar-h: 0` in the frame's prelude only (Q10), so `./enhance` hosts keep the documented 48 px; `chrome.topSpace` (default true) (Q8). (2) The answers to Q7 to Q12 and Q15 are the operator's recommendations as recorded in [C104](C104.md) (4); Q12 puts the running head and the overlay state report in Later. (3) Task 6's rulings, decided by the wave's controller during the task's review and ratified by the coordinator at review 1480 (T6-j is kept, review 1480 A7; T6-c's flag rule is refined by F2, see [C112](C112.md)). T6-a: `onProgress`'s share is a fraction in [0, 1] in `./enhance`, and the bridge sends `round(share * 1000)`, which the host hands back divided by 1000. T6-b: `topSpace: false` takes effect only on a root with no bar. T6-c: a host's own button toggles, so a second press closes; the frame's menu does not close when focus leaves the document, and in one document a command that arrives in the same gesture whose pointerdown just closed the menu leaves it closed. T6-d: a command closes its own overlay if open and opens only when no other overlay is open, as the keys refuse; otherwise it answers false. T6-e: `contents` where the rail is shown (1240 px and wider) answers false. T6-f: `onProgress` reports the initial share once at start, then every change. T6-g: a stored Outline is applied at start. T6-h (B6p, the registry's known-name check) is an equivalent mutant: a map lookup does no prototype lookup and `register` throws for an unknown name, so the check stays only for type narrowing. B6ac and B6ad are equivalent mutants: a non-key lookup answers undefined, and the registry refuses a non-string name. T6-i: the extra fix rounds ([C110](C110.md) (2)). T6-j: in settings, a `focusout` naming no element never closes the menu; focus moving to another element outside the menu does. Parked, as it stands after review 1480's F2 fix: a press outside the reader that sends no click and none of the events that end the gesture (a release outside the window, say) leaves the gesture's flag until the next press, so a settings command run from the keyboard in between is swallowed once; and a second pointer between press and click clears the flag early, so that click reopens the menu; each costs one extra press on a host with the bar off. Parked too (review 1494, F8): an `./enhance` host element outside the root whose click handler stops propagation leaves the flag set after an outside press, so the host's next keyboard `settings` command is swallowed once. (A right or middle outside press no longer leaves the flag: its auxclick or contextmenu clears it, since fix round 4; a tap on a card's trigger, whose click the reader stops, no longer leaves it either: a click inside the reader's root now ends the gesture, F2.) (4) Task 7's rulings, decided by the wave's controller during the task's review and ratified by the coordinator at review 1480. T7-a: `DocFrame.command` checks the name before the state, so an unknown name throws even before `ready` or after destroy. T7-b: a queued progress value coalesces in place in the outbox, so at most one waits and a later navigate is never queued behind stale progress. T7-c: the frame, not the host, keeps the four reports a second. B7q, B7s and B7z are equivalent mutants (the destroyed return and the command resets overlap with the `live` check); a size check on the key set was removed as unreachable, since the key set refuses extra keys and B7ac measures it. (5) Task 8's rulings, decided by the wave's controller during the task's review and ratified by the coordinator at review 1480. T8-a, BX-4: `test/browser/host-frame.test.ts` is left unchanged although the plan lists it, because it pins no adapter list, `DocFrame` shape, `--bar-h` or command; the one-bar rows live in `test/browser/frame-one-bar.test.ts` on the same host page. Parked: dropping `iframe.focus()` (B8b) stays green in B8.1 on Chromium because the opened tool focuses itself, and is red where no tool moves focus (B8.3 at 1440 px, B8.1c); B8.2's target lands at the reader's scroll margin (14 px with the bar off, 62 px with it on), the documented anchor offset. (6) B8.5, measured on Chromium at 390 px: the title's top is 59.73 px below the iframe's top with the bar off and `topSpace` true, 39.73 px with `topSpace` false, and 108.73 px with the bar on; the root's top padding goes from 28 px to 8 px, and 32 px of the 40 that remain is the eyebrow line, so the 8 px of Q8 is exactly the padding and stands. WebKit figures: Chromium only here; the browser rows run on both engines in CI.

## Why

The operator's answers and the controller's task-level rulings, written where the next change reads them.

## Cost if wrong

A trim value or a command's refusal rule, each one constant or one branch.
