# C103: The copy check flags the directional marks and the tag characters

*Recorded 2026-11-02, operator, recorded by the coordinator.* · [Decision log](README.md)

> [!NOTE]
> Amended by [C106](C106.md) and [C109](C109.md); read them with this one.

## Decision

The first consumer's W8a review found that the check lets U+200E LEFT-TO-RIGHT MARK, U+200F RIGHT-TO-LEFT MARK, U+061C ARABIC LETTER MARK and the tag characters U+E0000 to U+E007F through: the marks can reorder the neutral characters shown around them, and the tag characters can carry a whole invisible text inside a copy ("ASCII smuggling"), which matters most where a copy is pasted into a model's prompt. Asked whether to add them, the operator answered "Add all four - it makes sense". (1) `hiddenChars` and `hasHiddenChar` (`src/host/copy.ts`) list the three marks by name, and every code point of the tag block: `LANGUAGE TAG`, `CANCEL TAG`, `TAG ` plus the Unicode name of the ASCII twin for U+E0020 to U+E007E, and the code point label `<reserved-XXXXX>` for the unassigned U+E0000 and U+E0002 to U+E001F (all 128 checked against Python's `unicodedata`, Unicode 16.0.0: no mismatch). (2) The tag characters are outside the BMP, so both functions walk by code point. `index` is still the character's first UTF-16 code unit, so a consumer that replaces a listed character in place must take two code units for a code point above U+FFFF. (3) The link classifier refuses an href holding any listed character, so such an href is now refused too: the one table serves both, as Task 9 built it. (4) U+2028 and U+2029 were not part of the ruling and stay unflagged. (5) Mutation rows L3.H7h to L3.H7s in `l3-mutations/task-9.md`; L3.H7g is re-targeted at the new loop, and every L3.H7 row was re-measured on the final tree, each red through assertions only (75 rows, 75 red). The review (three lenses) found no defect in the scan: one lens ran every code point through it and every name through `unicodedata`. It found three gaps in the proof, all fixed before the merge: L3.H7g's text no longer occurred in the file, the step past a code point above U+FFFF had no test (`>=` for `>` survived; now L3.H7q and L3.H7r), and the order of the ASCII name table was unpinned (now a test of all 95 names against a list the test derives, and L3.H7s). Carried, not fixed: a percent-encoded hidden character in an href (`%E2%80%8E`) still reaches the classifier's other checks unflagged, as before this change; the classifier claims nothing about encoded forms. (6) It ships as a patch, 1.0.1: nothing under the frame's build imports `src/host/copy.ts`, so no asset hash moves (CHANGELOG's rule).

## Why

The operator's ruling.

## Cost if wrong

An occasional extra confirmation on a copy of Hebrew, Arabic or Persian text, or of a subdivision flag emoji; a copy is never blocked.
