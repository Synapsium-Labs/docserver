# C81: The L3 design rulings

*Recorded 2026-10-26, coordinator.* · [Decision log](README.md)

## Decision

Three independent designs (consumer contract, security, packaging and release), two judges, a synthesis and a completeness critic produced the L3 design; the critic's seven major gaps were ruled as follows, and the plan carries them as "ruling R1" to "R7". R1: the hash grammar accepts every id the layout can go to (heading slugs, anchor ids, footnote ids with a colon, and defined IDs with a dot); an id outside it is never sent and never thrown on. R2: the free-global scan covers static member reads on `globalThis`, `window` and `self` as well as unbound reads, and every listed name is pinned before content exists. R3: the seed's HTML is materialised once in the frame, bounded by a cap derived from the 2 MiB document cap and the corpus's measured ratio, and its time is measured as an input to the first consumer's E17. R4: v1 ships the spec's on-tap Mermaid contingency as an enhance option. R5: the parent's limits read as token buckets; the frame paces itself so that neither a bucket nor a strict sliding window can refuse it. R6: escape sequences are written visibly in every committed text. R7: the host page that uses `./host` must not block the frame's hashes, inline style or data: assets, which the README states and browser rows pin. Defaults were taken for the remaining design questions and are listed in the plan for the operator's review.

## Why

Each gap would otherwise have reached a task as an ambiguity or a refused ordinary read.

## Cost if wrong

A default the operator overturns changes a task before it runs, not after.
