# C88: Task 9's rulings

*Recorded 2026-10-27, coordinator.* · [Decision log](README.md)

## Decision

(1) `./host`'s produced interfaces are the shipped ones: `parseBridgeMessage(data, ports, nonce)`, because the conformance fixtures make a `ready` with a wrong nonce or version a parser refusal, and `createLimiter({clock, deliver})` with `admit`, `refuse`, `changesDone` and `dispose`, because a coalesced `navigate` or `version` is delivered when its window ends; the caller owns the 30 s deadline of a `changes` and calls `changesDone`. The plan's Produces line and Reference §11.3 are amended; Task 10 and Task 5's L3.M12 consume these. (2) Every op, `error` included, takes a general token: a terminal `error` refused at an empty bucket counts toward the sixteen like any other, as the fixtures' rules say. (3) The copy check also lists the [C1](C1.md) controls, U+0080 to U+009F: a terminal reads U+009B (CSI) as the start of an escape sequence, so copied text holding one is shown, never written silently. This widens Reference §11.3 and the first consumer's M8.19, the safe direction; the first consumer's spec takes it as a suggested amendment through its W8 plan. (4) A second `changes` in flight is refused and counted toward the sixteen; the first consumer's spec says "dropped", and a frame following the contract never sends one. (5) The store keeps its write order under the reader prefix (`meta:written`), because Web Storage records none and eviction needs it. (6) Task 10, which adds the DOM-dependent mount, splits `src/host` and its tests out of the root typecheck project; until Task 12 wires the exports, `tsconfig.build.json` keeps `src/host` out of the build, pinned by a test.

## Why

Each is the closest faithful reading of the plan and the fixtures that the code could meet.

## Cost if wrong

A consumer that copied the spec's narrower list or its "dropped" wording behaves differently from `./host` in two cases a conforming frame does not produce.
