# C39: A sequence as a merge source fails the load

*Recorded 2026-10-15, the coordinator's re-review of L1's fix round, run 464.* · [Decision log](README.md)

## Decision

A `<<` merge list that held a sequence merged it as a mapping with keys `0`, `1` and so on. For example, `tags: &t [alpha, beta]` then `<<: [*t]` rendered `0: alpha` and `1: beta`. PyYAML refuses that block ("expected a mapping for merging"), so the reference renders nothing. Ruled: a merge source that is not a mapping fails the load, through the same path as [C33](C31.md). That restores parity, so it is no departure. A unit case pins both outputs.

## Why

[C33](C31.md) chose parity over documenting for a key shape that no author means, and this is the same kind of shape.

## Cost if wrong

Such a block renders nothing, as it does in the reference.
