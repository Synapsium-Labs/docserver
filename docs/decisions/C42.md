# C42: `destroyEnhancement(root)` returns `Promise<void>`, which settles after cleanup

*Recorded 2026-10-19, operator.* · [Decision log](README.md)

## Decision

A destroy inside one of the reader's own actions defers the teardown until the action unwinds (the operator's ruling). As built, the destroy marks the instance destroying at once, so every write the action attempts after it is refused, and the teardown runs as the action unwinds.

## Why

A host can await cleanup before it reuses the root, and no action writes after a destroy.

## Cost if wrong

A host must handle a rejection (an `AggregateError` from a failed cleanup step). The promise is marked handled, so an ignored one is not an unhandled rejection.
