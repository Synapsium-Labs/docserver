# C55: The group D handoffs

*Recorded 2026-10-21, coordinator, from the integration checks and reviews of Tasks 14, 17, 20 and 21.* · [Decision log](README.md)

## Decision

- **History is preserved from here on.** This supersedes [C50](C50.md)'s and [C52](C52.md)'s rebase procedures and the plan's corresponding stack procedure. Absorbing main requires one of three measured triggers: a conflict (`git fetch origin` then `git merge-tree --write-tree --name-only --no-messages HEAD origin/HEAD`, exit 1 with a tree id first); a required PR check that is red while its failing files pass on a clean main checkout; or the coordinator's landing-line instruction naming this PR ejected with a base SHA or next to land in a strict-protection repository. The first two triggers license at most one absorption per PR: a second occurrence before the first absorption lands is not a second license. Exit 0 is clean; any other probe answer is unmeasured and licenses nothing. A failure also reproduced on main is reported once as main-red, not cured by absorbing main. Otherwise a clean branch lands as it is. An authorised absorb uses an ordinary `git merge`, never a rebase, force push or update-branch operation. Task 12's published ancestry was joined by a merge whose tree is identical to the already verified integration tree; it was pushed normally. [C54](C54.md)'s combined-test requirement remains; its "each squash" wording grants neither a history rewrite nor a main sync. This changes no repository settings or merge permissions.
- **Navigation's browser oracle reads the physical table head.** The initial heading assertion passed; the subsequent no-id row assertion hard-coded the 40 px fallback even after the tables measured a 35-36 px head. Task 14 now derives the expected room from `thead.offsetHeight`, independently of navigation's `--thead-h` read, keeping the 1 px tolerance and the heading assertion. Native `tr[id]` scrolling agrees. No production navigation or pin change is warranted. M160 and M161 each fail when the measured height is ignored or never written. Task 14's quick-jump mock also leaves out the real position feature it impersonates.
- **The standalone style-journal browser case runs without the real bar.** The bar legitimately replaces `--bar-h` during relayout; the case now sets `chrome.bar: false` and waits for the CSP report itself (#33). A repeated green run on the old branch is not the fix.
- **Task 17 may extend the browser harness with optional `hasTouch`,** passed to the browser context, and add a tracked real-tap regression. The first tap previews and the second follows in Chromium and WebKit, even when WebKit names the tap's click `mouse`. A keyboard click (`detail: 0`) follows immediately. Existing pointer freshness, focus-return and card-text-press fixes stand; each has measured rows. Its lazy card, id, overlay and scroll listener are accepted: nothing is registered before first use, and no visible behaviour changes. The literal chrome-attribute spelling stays because the CSP wall refuses a variable attribute name outside the journal, with its drift test and M196 retained.
- **The Cards lazy-accounting diagnostic has one bounded fixture exception.** Its single test may use a false-by-default, hoisted pass-through features fixture which excludes only jump, keysheet and scroll; the other 90 cases retain every feature. The existing zero-before-use, listener, id, overlay and reuse guarantees are unchanged. The current trace produces two ids and one listener; the diagnostic has 91 green cases and seven red mutants. Implementation remains ongoing and is not a completed result.
- **Task 18's root observer ignores width-unchanged, height-only reports.** Its regression is independently flushed and is not a loop test.

Task 19 may narrowly extend `state.ts`'s `applyPrefs` to journal the `lens-product` class beside the other root preferences and update its ownership comment. Lifecycle already calls that one writer at startup and on preference changes; no duplicate lifecycle or settings-menu class writer is added. Attention still owns the peek bars. Regression cases cover initial and stored preferences without the menu, host updates, two roots and conditional teardown; deleting the class write must make a case red. This is a writer exception, not evidence that the unfinished task has passed.

Work paused temporarily and then continued on the selected `applyPrefs` design. It remains under implementation and has not yet been verified complete.
- **Task 20's strip remains three facts, with no new front-matter scalar defaults.** [C44](C44.md)(c) stands after its requested revisit. The coordinator's shared-test fixes stand: the services mock leaves out `strip`, and the editorial facts case looks past `.review-strip`.
- **Task 20's navigation oracle is test-only.** Its heading-text clone removes only `.h-ctl` and keeps the source label `.sec-no`; no-id paragraph navigation uses `window.scrollTo`. The destroyed-show cases keep both scrolling primitives -- `window.scrollTo` and the element's `scrollIntoView` -- at zero and leave the flash absent, including `onHide` and changes reentrance, and do not read target layout after destroy.
