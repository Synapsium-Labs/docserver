# C72: Fullscreen owns pointer qualification for its diagram blocks

*Recorded 2026-10-25, coordinator.* · [Decision log](README.md)

## Decision

The cards root-capture click handler runs before the viewer stage's handlers, so an unqualified compatibility click after a drag can otherwise show a card. In `cards.ts`, the `.dnode` click branch skips only a block inside this root's open figure viewer stage; the viewer opens that block through existing `cards.show` only on a qualified pointer-up. Keyboard Enter/Space, preview-card navigation, ordinary text triggers, and diagram blocks outside the viewer keep their existing behavior. No listener reordering, new public callback, event framework or generic suppression API is introduced.

The change ships with a valid defined-block fixture, a passing tap control and a red-before-fix drag/cancel/long-press click control. A fixture must establish the cloned block's data reference and a real definition before judging card behavior; a failed fixture expectation is not proof of the production defect. Run the complete cards unit and browser files as well as the viewer controls.

## Why

Pointer capture makes the stage the authority on gesture qualification, but the root still sees the compatibility click first.

## Cost if wrong

An explicit click path in the viewer could stop previewing; the pointer-up and keyboard controls preserve both user paths.
