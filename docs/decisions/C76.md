# C76: Preserve normal prose flow when placing the desktop rail

*Recorded 2026-10-25, coordinator.* · [Decision log](README.md)

## Decision

Actual reference comparison exposes larger list bounds and vertical gaps because desktop source blocks became grid items, suppressing native margin collapse. Restore normal block flow with one root-owned rail gutter and a sticky float; retain the existing rail, source-column, bar, breakpoint, print and independent-root geometry. No source wrapper, public API or scheduling change follows. A measured browser control fails by 8.09375px on list height before the correction and passes afterwards, together with the unchanged physical rail bounds and an offset-root containment check. Restore the dark code wrapper to the existing text token rather than a separate hard-coded colour; its measured colour control fails before and passes after.

## Why

The binding palette and prose rhythm are parity requirements, not incidental effects of the placement model.

## Cost if wrong

Float containment could differ in an embed; the two-root and unchanged rail bounds are mandatory, and both-browser CI remains outstanding.
