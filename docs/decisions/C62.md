# C62: The source-only fold correction has a bounded core writer scope under C60

*Recorded 2026-10-21, coordinator.* · [Decision log](README.md)

## Decision

This resolves the final contract review's ambiguous interval wording by preserving each already-held association, not the identity of a trailing endpoint. It is implementation permission, not acceptance.
- Only `src/enhance/reading.ts`, `src/enhance/folds.ts`, the existing `folds: createFolds(root)` call in `src/enhance/lifecycle.ts`, and new dedicated `test/enhance-fold-source.test.ts` and `test/browser/fold-source.test.ts` may change in the core correction. The lifecycle change is that constructor argument only, at its current location after initial storage and pending preferences and before features; no phase, order, context, public API or other lifecycle change is included.
- Capture original direct-child identities and compact integer reading contributions, not cloned DOM or text strings. At the existing fold scan, map those originals to their current exact source-bearing direct-child presentation members under the existing h2 and nested-h2 stop conditions. Count each captured original once and keep zero-contribution originals as members; chrome-only blocks and later source insertions cannot create a section. An h1 remains an ordinary member, not a new fold boundary. Sum integers before the section's one conversion; preserve the existing whitespace, member exclusions, nested-code/figure rules and whole-document per-section summation order.
- Hold the scan's associations across the stored-fold getter. An association is valid only while its captured original still maps to the exact held direct-root-child presentation member, its held heading is still an eligible direct h2 with a nonempty id, and the member still follows that heading without an intervening existing fold-stop condition. A member that now contains h2 is invalid. Removing the old trailing boundary alone keeps valid held members, but absorbs no later member; an inserted or replaced boundary before a member invalidates that association. A replacement presentation wrapper inherits nothing. Partial source loss drops only invalid originals and their counts; no association is transferred or reconstructed.
- Read stored folds, validate, then create controls and hidden state. Keep the captured section id for stored selection and retain the empty/false/no-effect prebuild facade. Apply the same validity rule at stale-sensitive operations, including after storage callbacks and before forward hidden writes, source lookup or joining a feature node. Preserve invalid inserted-node rejection after build, exact-member join semantics, conditional undo and startup error propagation. Consume unused source capture on disabled, non-document and empty builds; startup aborts retain no new cleanup contract.
- Permanent assertion reds precede source edits. Cover removed, replaced and inserted boundaries; partial and complete source loss inside a retained wrapper; post-save invalidation; h1 membership; source epochs; mixed integer arithmetic and the 345-word rounding edge; prebuild and postbuild joins; destroy and rollback. Run both browsers, unchanged walls and all TypeScript projects, exact semantic reversals and restored controls, and the full suite with every failure preserved. Existing corpus, goldens, geometry, RF3, CSP and scanner limits stay unchanged.
- Attention's deferred join completion remains a separate proposed writer exception. This core grant touches neither `attention.ts` nor `settings.ts`, adds no cross-feature completion export, and does not change the table or menu workers' ownership. No Task 18, Task 19, combined-group or required-model gate closes.

## Why

The diagnosed fold counts currently include chrome and can create an empty final fold, while stored-fold callbacks can invalidate held source.

## Cost if wrong

Source capture and stale rejection can lose valid members or change arithmetic, so exact identities, preserved associations and independent semantic reversals are required.
