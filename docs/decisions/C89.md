# C89: The browser install's apt cache refreshes weekly

*Recorded 2026-10-27, coordinator.* · [Decision log](README.md)

## Decision

The Task 17 follow-up (#51) caches apt's downloaded packages under a key ending in the ISO week, with the earlier weeks as a fallback, so the cache refreshes as Ubuntu publishes new packages; this reverses the brief's "no fallback key" for that cache only, and the browser cache keeps its exact key. The archive directory lives under `/var/cache`, owned by the runner and reachable by apt's sandboxed download user, and the repair step between attempts is bounded at 40 s inside the step's budget. Measured on #51's own CI: the cold job saved the cache; the other job met a stall, its first attempt timed out, and the second reused the first's partial downloads and finished.

## Why

A cache that never refreshes stops preventing the stall it exists for.

## Cost if wrong

Superseded packages accumulate until the pinned browser version or the OS release moves.
