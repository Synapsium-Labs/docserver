# C68: The final corpus records the completed reader controls, not the earlier stubs

*Recorded 2026-10-25, coordinator.* · [Decision log](README.md)

## Decision

The combined layout run reports seven structural mismatches. Inspection of the retained differences and the corresponding implementation/reference establishes the following intended additions only:
- `core/anchors`, `core/clobbering`, `core/folds`, `nav/names` and `nav/stored` gain the read-mark button within each existing heading-control group. Existing anchors, folding state, source text and clobbering coverage remain unchanged.
- `jump/no-keyboard` gains the closed Keys sheet and its colour key. `keyboard: false` disables shortcuts, not the explicitly opened Keys control or shared Escape handling; the existing quick-jump controls and keyboard-disabled checks remain.
- `rail/marks-index` gains the reference's separate count, group-title/count, ID/title and status-dot elements. Entry identities, order, group fold state, active state, read marks, labels and destinations remain unchanged.
- Task 24 may update exactly these seven expected DOM files after checking the actual full diff against this list. It must retain the hostile inputs and verdicts, run the renamed-ID/prototype controls, name every moved case in the final `Layout-moved:` trailers and release notes, and submit the resulting delta for independent review. Any other difference requires diagnosis before an expected file changes. No mass snapshot update, ignored node, excluded feature or weaker comparison is authorized.

## Why

Holding the snapshots to unfinished stubs would remove the approved reader features rather than verify them.

## Cost if wrong

An unintended DOM change could be accepted; the exact additions, unchanged hostile probes, full diff and ratchet keep that decision reviewable.
