# C102: v1.0.0 is released

*Recorded 2026-10-31, coordinator.* · [Decision log](README.md)

## Decision

(1) Q9: the operator's key (ED25519, `SHA256:+t7W33ECSXbsX0w4muCbYQ5o1Xvp23h9VMJHmnBv8nU`) was copied verbatim into `.github/release-signers` in the release pull request #75 (version 1.0.0, `private` removed, the flipped pin, `assets.json`'s version, the CHANGELOG entry naming all 13 asset hashes, the README status line, and as consequences the lockfile's root entries and the pack row's tarball name). Before merging: mutation rows (`private` put back, 2 red; the key line removed, 1 red), and a throwaway-key `git verify-tag` against the file, which parsed it and refused a foreign key. The review (three lenses and a refute pass) found no defect. Its one refuted finding was accurate all the same: a published placeholder makes "the first published version" false. So the documents call 1.0.0 the first release. (2) Q5: the operator published the placeholder `0.0.0-reserve` by hand. npm 11 refuses a prerelease without a tag, so it went out with `--tag reserve`. npm itself published a second empty version, `0.0.0-stage` ("Temporary package placeholder for staged publishing"), a minute earlier in that first publish. Both are deprecated, and #76 names both in the README, the CHANGELOG and SECURITY.md. The trusted publisher was attached with `npm trust github` (workflow `release.yml`, environment `npm-release`, publish allowed). (3) The tag: the annotated `v1.0.0` on 247b776 (`main` after #76), signed with the operator's key on the operator's own machine and pushed by the operator. The release-tags ruleset reported its administrator bypass, as designed. (4) Release run 41220398420 succeeded in every job: verify-tag's six checks (check 6's first live read: the job's token sees `can_admins_bypass`), the tests on Node 22 and 24, build, attest, publish (after the operator's approval in `npm-release`), github-release and post-verify. (5) Task 15's acceptance, re-run by hand in a scratch directory: the five Release verification commands each exit 0 (15 packages with verified registry signatures, 2 with verified attestations). The attestation is SLSA provenance v1, signed by `release.yml` at `refs/tags/v1.0.0` for commit 247b776. `dist.integrity` equals the sha512 of the registry's tarball. The GitHub release (not a prerelease) carries the tarball, `SHA256SUMS`, `assets.json` and the attestation bundle, and its `SHA256SUMS` gives the npm tarball's sha256 (`a23a1317…`). npm's `latest` is 1.0.0. (6) Not measured here: whether the package's publishing access is set to require two-factor authentication and disallow tokens, which needs the owner's npm login. The `reserve` dist-tag still names the placeholder. (7) What remains of the programme: Task 13 (Mermaid 12.2.0) as a later minor ([C93](C93.md)), the integration into ccrc, and retiring the standalone docs service.
