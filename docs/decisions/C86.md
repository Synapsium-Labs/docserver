# C86: Task 1's three rulings

*Recorded 2026-10-27, coordinator.* · [Decision log](README.md)

## Decision

(1) The frame's plain-data types (`CommitEntry`, `ChromeOptions`, `VocabularyOptions`, `FramePrefs`) are DOM-free copies in `src/frame/wire-types.ts`, held equal to the layout's own by a compile-time test in the DOM typecheck project; the plan's Reference §1 import from `../enhance/types.js` is superseded, because that module reaches DOM types and the frame source typechecks with no DOM library, and `src/enhance/types.ts` (Task 16's) stays untouched. (2) L3.M10 reads every non-empty id: `render()` writes `id=""` on an empty heading, which the hash grammar rightly refuses, and a separate row pins that only headings carry an empty id. (3) Mutation evidence: a type-level row counts as red when its mutant fails the typecheck with errors only on the test's `expectTypeOf` lines, since `npm run typecheck` gates CI; and a row that mutates a defensive check no input can reach is recorded as an equivalent mutant, never counted red, with the check kept, as [C78](C78.md) did for overlapping guards.

## Why

Each was the closest faithful reading of the plan that the code could meet.

## Cost if wrong

A copy that drifts from the layout fails the typecheck; an unreachable check that becomes reachable needs its own red row.
