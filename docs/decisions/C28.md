The worker put the review's open questions as one batched question. The operator answered it in the worker's own dialog at 12:49Z and chose the recommended option each time. It is recorded here after the fact, because the question never reached the coordinator's ask lane.
- **C28: the figure caption is bounded, with no change to the output.** The caption rule rendered the whole candidate paragraph at parse time. That was outside `render()`'s html bound, and also inside `scanRefs()`, which has no bound. A caption of links that repeat one long destination built a 1 GB string: a fatal out-of-memory error at 3.0 MB of input, and a `failed` outcome plus a thrown `RangeError` at 3.9 MB, which is under `maxBytes`. The rule now decides from tokens: one emphasis span ([C25](C25.md)), then the `Figure N.` test on a bounded prefix. The caption renders in the render phase, under the html bound. Every golden is byte-identical. The corpus and 39 caption shapes agree (corrected 2026-10-15: an earlier version of this entry said 41 shapes, and named a 60,000-document fuzz run that was never committed as a test). The fix round's differential over 1,439 candidates found no difference. There is no generated corpus case: the 9,238 bytes left under the corpus's 8 MiB cap cannot reach the 16 MiB html bound. Unit cases and 25 mutation rows pin it instead.
- **C29: PD9, heading ids follow the runtime's Unicode tables.** The slug keeps `\p{L}` and `\p{N}` and lower-cases the way the runtime does. So a code point that was unassigned in Unicode 15.0, the reference's version, can appear in an id where the reference dropped it, and two runtimes with different Unicode versions can disagree. It is documented in the README, with a unit case gated on the runtime's Unicode version, and no code change. No golden reaches it. This makes the departure list PD1-PD9.
- **C30: highlight span depth is accepted and documented.** A single highlighted line of 256 units can nest highlight.js spans up to about 170 deep. That is above [C21](C21.md)'s 64, but [C21](C21.md) covers the allowlisted tags only. The line cap and the whole-block threshold bound it, well under browsers' parse limits. The README states the bound.
- **Fixed within existing constraints:** the CI consumer smoke installs with a 14-day `--before`, and its checkout keeps no credentials. The whole-block threshold is pinned by its literal size. A comment in the shipped types is reworded. The README tells hosts to size `maxBytes` to their heap.
