# C63: Relayout may distinguish an already-measured startup width from a genuine first root-width change

*Recorded 2026-10-21, coordinator.* · [Decision log](README.md)

## Decision

This is a bounded source and [C54](C54.md) shared-test exception, not Task 18 or group acceptance.
- **Sole source writer:** `src/enhance/relayout.ts`. At the run containing `start`, sample a conservative synchronous content width immediately before the existing measuring listeners and again after they finish, while live and before the public relayout event. Seed the root-width cache only when both samples are known, exactly equal and the listeners completed without faults; otherwise forget the baseline. No construction-time, scheduling-time or post-event seed is accepted. A synchronous public event callback's later width change must still trigger. A measuring listener that changes width and restores it before completion is not universally detectable; this grants no atomicity across arbitrary host DOM changes.
- **Known shapes only:** a connected XHTML element other than `html` or `body`, exactly one client rect, computed display `block` or `grid`, horizontal writing mode, visible overflow on both axes, automatic or unsupported gutter, and no column fragmentation. Read through existing `env.computed`; accept only strict finite nonnegative resolved pixel dimensions and supported content-box or border-box sizing. For border-box subtract resolved horizontal padding and borders; preserve fractions and ignore transforms. Unsupported or ambiguous shapes remain unknown, never zero. Bounding widths, integer client widths, a new environment API or stylesheet changes are not substitutes. Finite two-browser block/grid probes support these shapes, not universal box-model equivalence.
- **Observer ordering:** before the actual startup measurement finishes, root reports need no additional resize because the production lifecycle guarantees the pending start measurement. Startup then replaces any earlier cache with its covered width or unknown. After startup, every finite different width triggers, including the first report when unknown and zero as a real width. Reject foreign and nonfinite reports before changing the cache; ignore equal-width and height-only reports. Never blindly drop the first report. The two direct test consumers without startup have no root observer; do not claim every possible direct consumer starts. Window debounce, fonts, no-observer and teardown behavior stay unchanged.
- **Exact shared-test scope:** in `test/browser/services.test.ts`, change only the late-stylesheet case and its explanatory header. Hold fonts across stylesheet attachment, prove the actual content-width change, require a fallback start followed by its fallback resize, then exactly one loaded-font run. The separate width-stable held-font case remains unchanged and strict. In `test/browser/blocks.test.ts`, change only the held-font and hidden-root cases: require the genuine narrowing resize while fonts are held, then independently change head height at stable width and require font release to remeasure; a revealed root must measure automatically without a manual request or viewport resize first. Retain hidden-state absence and post-destroy no-work coverage. All other cases remain unchanged.
- **Permanent discriminators:** new dedicated `test/enhance-relayout-baseline.test.ts` and `test/browser/relayout-baseline.test.ts` cover equal and changed first reports, unknown hidden-to-visible without a zero report, independently flushed width and height changes, invalid-report cache poisoning, fractional and transformed boxes, guarded eligibility, measurement/event timing and teardown. The real 1440 px reader with its actual rail and stylesheet must show only fallback start before font release and one loaded-font run afterward, with first observer delivery after completed start; excluding grid must fail that assertion. A separate changed-first-report case must reject blind suppression. Real assertion reds precede source edits, exact semantic mutants restore green, and both browsers, all TypeScript projects, unchanged walls and the full named-failure census remain required.
- Existing lifecycle, environment, context, feature order, source table/code, CSS, harness, configuration, scanners, corpus, goldens, RF3 and geometry limits remain readonly. No attention completion export, concurrent fold/rail writer overlap, required-model waiver or task/group acceptance follows.

## Why

The first observer delivery can repeat geometry already measured at startup, but it can also be the first evidence of a genuine width change.

## Cost if wrong

An incorrect baseline could hide that change or schedule a redundant fallback run, so unknown values remain conservative and the two situations have separate permanent cases.
