# C73: The progressive edge rule must win the figure cascade

*Recorded 2026-10-25, coordinator.* · [Decision log](README.md)

## Decision

The real-browser playback control measures `0.38s` instead of the required `0.55s`: the figure-scoped opacity selector has equal class/attribute specificity and more type selectors than the later generic `rv-draw` rule. Add the corresponding figure-scoped `path.flowchart-link.rv-draw` selector alongside the existing root-scoped rule, retaining `transition: stroke-dashoffset .55s ease`. The generic rule still covers a detached figure viewer clone; ordinary figure elements retain their opacity transition outside progressive drawing. No `!important`, direct style setter, new property permission, palette change or duration/tolerance relaxation is authorized. The reduced-motion override remains authoritative.

The existing red browser control must turn green for both the computed transition property and duration, with cleanup returning the edge to its ordinary transition and reduced motion still disabling transitions. Run the complete affected diagram browser file and style guards.

## Why

Class changes alone do not implement the required animation when the cascade discards its transition.

## Cost if wrong

The edge could lose its ordinary reveal fade; explicit drawing, cleanup and reduced-motion controls bound that change.
