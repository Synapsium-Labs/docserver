# C97: Task 10's rulings

*Recorded 2026-10-28, coordinator.* · [Decision log](README.md)

## Decision

(1) The typecheck split of [C88](C88.md)(6) is `tsconfig.host.json`, holding `src/host` and its tests with Node's types for the tests; `src/host` itself stays free of Node APIs, proved by a walls row that compiles it alone with the DOM library and `types: []` (a planted `Buffer` control goes red). This edits Task 9's pin in `test/host-parse.test.ts`; the alternative, a separate project for the host tests, would have changed `package.json`'s `typecheck` script, which Task 10 does not own. (2) Accepted: `test/browser/frame-host-page.ts` serves a page that mounts through the real library, and `frame-shared.ts`'s progress wait accepts it (reuse, not copies); `test/host-mount.test.ts` runs in Node with its own JSDOM instance, because vitest's jsdom environment replaces the global `Uint8Array` and `URL` that the in-memory frame build needs (measured); `./host` checks a `changes` answer against its own `HOST_CHANGES_MAX` (10,000), held equal to the frame's caps by a unit row rather than by importing the frame runtime into `./host`. (3) The readings the plan left open: ops dropped before ready count toward the sixteen refusals and carry into the limiter at ready; a second `ready` is refused and counted; a `navigate` that `classifyLink` refuses is dropped uncounted, as host policy rather than a protocol fault; unknown adapter keys throw `TypeError`, as the reader's options do; `title` is 1 to 1,024 code units; `focus` is a boolean; `update()` after a fallback mounts again, while `update()` and `setPrefs()` after `destroy()` do nothing (`setPrefs` still checks its argument); `setPrefs` merges into the seed of every later mount; `destroy()` called by host code inside `update()` tears down the mount being made. (4) L3.HB6's "drop the registration check" is read as the bootstrap's "no enhance registered gives `FAILED('assets')`"; without it the frame still fails, with `render`, so the HB6 rows read `why` from what the frame posts, carried out through its console. (5) The exfiltration fixture carries two more fields. `throws` lists, per channel, only the exceptions an engine throws when it refuses at the call (`SecurityError` for WebSocket, EventSource, the two workers and the service worker); every attempt must answer or throw one of those, so a frame that was never reached cannot pass, and the list is never widened to make a row pass: an unlisted exception on an engine is a finding for the coordinator. Channel 17 (`<track src>`) sets `crossOrigin = 'anonymous'` on its media element, because Chromium fetches a text track from another origin only then; no channel is dropped. The mounted battery is backed by a same-page probe from the main frame that must reach at least 20 channels, so its zero is a measurement. (6) `HostChanges` is not exported: the entry's types are exactly the Produces line's. (7) The walls scan flags every guarded string and name in any spelling (element access, `Reflect.set`, `Object.defineProperty`, `Object.assign`, destructuring), with fifteen planted spellings as controls. (8) The Hosting section's text, Reference §11.5's host-page policy and its three fallback outcomes, is handed to Task 12, which owns the README. (9) On WebKit, Playwright's route log also lists `blob:` URLs: 22 in L3.HB1's mounted row on CI, 11 created by the frame (`blob:null/…`) and 11 by the host page. No channel creates one. A `blob:` URL is read inside the browser and never leaves it, so the row's extra check that no other request appeared skips the `blob:` scheme and prints what it skipped. The plan's leak test, a request to origin A or B or a WebSocket event, is unchanged, and it read 0 on WebKit, with the control and the same-page probe each reaching 22.

## Why

Each is the closest faithful reading of Reference §11 that the code and the engines allow.

## Cost if wrong

A host that relied on an unlisted reading meets a refusal or a fallback where it expected delivery, which the jsdom rows pin.
