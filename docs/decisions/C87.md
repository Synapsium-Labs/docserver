# C87: The seed's html cap follows the plan's formula

*Recorded 2026-10-27, coordinator.* · [Decision log](README.md)

## Decision

Task 3 measured r = 27.3061 over the golden corpus (escaped html per markdown byte, fixed keys excluded), set by the 49-byte `nesting-limit.md`, so `SEED_HTML_MAX_CHARS` is 57,265,090, not the plan's estimate of about 21.1 million. The coordinator first ruled a 1 KiB floor for the ratio, on the reading that a tiny document's ratio is fixed per-document markup; measured, the corpus has one document over the floor, which gave r = 3.74 and a cap that would refuse a document as dense as `fences/main.md` at about 795 KB. That ruling is withdrawn before any commit: the ratio comes from nesting that a legal 2 MiB document can repeat, so the formula's figure is what FD17 ("no legal document refused by the default") requires. Risk R1 widens with it; a host lowers its own `maxSrcdocChars` after measuring, as the first consumer's W8 already plans. Also in Task 3: its interim edit to the bootstrap (Task 5's file) passes only Mermaid's caps until Task 16 adds `draw`, and its equivalent mutant L3.M4d falls under [C86](C86.md).

## Why

A cap below a legal document's real size refuses it.

## Cost if wrong

The default allows larger srcdocs than a host may want, which the host's own lower setting bounds.
