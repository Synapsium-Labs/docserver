# C91: Task 2's and Task 6's rulings

*Recorded 2026-10-27, coordinator.* · [Decision log](README.md)

## Decision

(1) [C86](C86.md) (3)'s equivalent-mutant class widens to one more kind: a mutation that changes only a spelling the build tool normalises away (Task 6's L3.M14b, an absolute input path that esbuild names relative to its working directory) is recorded as equivalent, never counted red, when a sibling row that changes the output bytes is red (L3.M14b2). Task 2's L3.M6q (splitting a policy on the space only) is an unreachable check under [C86](C86.md) (3) as written: the character rule refuses tab, line feed, form feed and carriage return before the tokeniser runs. (2) The free-global list goes into the bootstrap through esbuild's `define` as a plain array literal, not frozen as Reference §5.5 says: `define` cannot carry an `Object.freeze` call, and the list exists only at its one use, where nothing else can reach it, so freezing it would change nothing observable. (3) Pinning makes eleven undeclared names inside Mermaid's bundled layout code read `undefined` instead of throwing a ReferenceError; that is the safe direction, and Task 8's diagram rows on both engines exercise those paths. (4) `CSP_REFUSALS` and its type are exported from `./frame` by Task 7 or Task 12, so a host can name a refusal.

## Why

Each is the closest faithful reading the build and the measured behaviour allow.

## Cost if wrong

A build-tool change that stops normalising input paths would make L3.M14b observable, which its red sibling already covers.
