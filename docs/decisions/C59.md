# C59: Task 19 may correct only the Aa colour-key heading selector in `assets/reader.css`

*Recorded 2026-10-21, coordinator.* · [Decision log](README.md)

## Decision

The root's generic paragraph margin wins over `.aa-kh`, making the heading-to-list gap and menu about 5 px taller than the reference. Strengthen only the existing selector to `[data-docreader-root][data-docreader-root][data-docreader-root] .aa-menu .aa-kh`; keep its declarations and the generic paragraph rule byte-for-byte. This is a scoped chrome override, not a global paragraph reset or a relaxation of [C57](C57.md).
- A new dedicated `test/browser/settings-menu.test.ts` uses real enhancement, the shipped stylesheet, the real Aa button and strict CSP. Pin the reference's 6 px heading-to-list gap within 0.1 px at 1440 and 390, light and dark. A known visible author paragraph must have positive dimensions and retain its independently expected generic margin: 18.9 px at 18 px desktop text and 17.85 px at 17 px phone text. Compare its unchanged geometry between original-selector and corrected-selector runs, and retain independently enhanced sibling-root controls. Hidden metadata with zero geometry is not a prose control.
- Reverse the exact selector and require a behavioral geometry assertion red, then restored green in Chromium and offline WebKit. No appended override, inline style, changed golden, scanner or tolerance; existing settings tests stay unchanged. Record evidence privately for later journal reconciliation, preserving historical rows.
- Menu anchoring stays unchanged: each menu already aligns to its own Aa button. [C48](C48.md)'s neutral ID example remains intentional. No vocabulary, feature order, folds API, source lifecycle, bar, rail or public API change is included. The private Chromium experiment establishes the measured gap and menu height, not whole rendering equivalence; strict-CSP, sibling-root and offline-WebKit verification remain implementation gates. No Task 19 or group acceptance follows.

## Why

Scoping the stylesheet to the enhanced root brought chrome under a stronger source-paragraph rule; the reference menu sat outside that source scope.

## Cost if wrong

The chrome override could affect author typography or another root, so visible-prose and sibling-root controls are required.
