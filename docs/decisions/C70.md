# C70: Fullscreen SVG cloning may rebind existing clone-local references through one internal journal operation

*Recorded 2026-10-25, coordinator.* · [Decision log](README.md)

## Decision

Task 23 must rename every clone ID while preserving references; LD11's ordinary measured-style setter deliberately refuses `url()`. A style-attribute write is not an acceptable substitute.
- The journal may create a detached deep SVG clone from a supplied drawing and a snapshot of its old-to-new ID map. The operation validates mapped source IDs and unique root-issued destination-ID syntax, includes the SVG root, marks clone elements as chrome, and never accepts a caller-supplied mutation target, CSS value, property, priority or replacement callback. It refuses when nonlive and checks liveness after supported DOM-method callouts; attaching and removing the returned clone still use existing ownership.
- On that new clone alone, CSSOM may replace already-present local fragment URL tokens whose IDs are in the map, retaining declaration priorities and other values. Unchanged declarations are not written. External URLs, unmapped fragments, colors and quoted text remain unchanged. The ordinary `setStyle` property/value/priority guards and conditional undo are unchanged; this is no generic resource-loading or arbitrary-style capability.
- Exact fragment hrefs, ARIA IDREF token lists and presentation-attribute local URLs use their distinct grammars. Embedded sanitized Mermaid style text may rebind mapped selector IDs outside comments/strings and mapped local URL tokens, never bare hashes in declaration values. Destination IDs are CSS-escaped. The clone preserves the source's rules rather than adding new styles. This is tested under the reader policy that already permits Mermaid styles; strict-policy CSSOM coverage uses a fixture without embedded inline style elements. No claim is made that a strict host policy can newly admit Mermaid's embedded styles.
- Tests first establish root/descendant IDs, local URL references and priorities, scoped rules, negative preservation and source immutability. Real browser checks prove clone-local paint, no new resource requests, CSP behavior and teardown; liveness tests use supported DOM-method reentry, not arbitrary scalar getters. Scanner changes are limited to exact additional journal CSSOM access counts with negative controls retaining feature-level style, serialized style, `cssText` and stylesheet bans. No network, parser dependency, public API, environment or lifecycle change is authorized.

## Why

Consistent clone IDs and CSP-safe style handling cannot be composed through the existing measured-style setter.

## Cost if wrong

Incomplete CSS-token handling could break cloned paint or scope; narrow input validation, unchanged source, reference-preservation negatives and real paint/CSP controls make that failure observable. No task or release acceptance follows from this ruling.
