# C38: PD2's C17(e) covers the order within a multi-source merge list

*Recorded 2026-10-14, during L1's fix round 1.* · [Decision log](README.md)

## Decision

With `<<: [{a: 1, c: 1}, {a: 2, b: 2}]`, the reference lists a, b, c, and `render()` lists a, c, b. With `x: 0` then `<<: [{a: 1}, {b: 2}]`, the reference lists b, a, x, and `render()` lists x, a, b. The values are identical; only the order differs. PyYAML reverses a merge list's sources and puts merged keys first. Ruled: [C17](C15.md)(e) now reads that merged keys follow JavaScript's object order. A late `<<` puts them last, and a multi-source list keeps its sources' order. Unit cases pin both outputs, and the README's PD2 row lists it.

## Why

This is the same class [C17](C15.md) accepted, from js-yaml and the object order rather than from a guard.

## Cost if wrong

Front-matter key order differs from the reference for merge lists, which no golden reaches.
