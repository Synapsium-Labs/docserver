# C58: Task 18's recovery correction is a bounded C54 shared-test exception, not implementation approval or Task 18/group D acceptance

*Recorded 2026-10-21, coordinator.* · [Decision log](README.md)

## Decision

Integration now means that synthetic seam ownership and read premises changed; the narrow exceptions below preserve the original guarantees without masking source regressions.
- **Startup seams and state.** `test/enhance-seams.test.ts` may extend its exact startup-read sequence to the actual once-only order and compute expected minutes from source before `enhance()`, preserving the boundaries, members, fingerprint, and script/dl exclusions. Only its two individual cases whose stated premise is that a UI key was never read may false-by-default omit the real rail; all other cases retain all features. Cached UI values read at startup are legitimate and `state.ts` must not discard them. `test/enhance-state.test.ts` may add the legitimate marks, UI and index-fold reads in actual once-only order, while keeping prefs-first and post-startup-no-extra-reads assertions unchanged. This authorizes no state-source edit.
- **Jump and plans fixtures.** In `test/enhance-jump.test.ts`, the fake drawer case may omit only the rail it impersonates. A case that impersonates position's `j`/`k` bindings may false-by-default omit only position; normal sheet cases retain and assert the real bindings. With `keyboard: false`, the oracle is a closed existing sheet with no `?` binding and no opening on `?`; the real Keys button opens it and cleanup removes it. Integrated real rail/jump/position cases separately prove that navigation closes the drawer, closing jump does not, the proper key rows appear, and `keyboard: false` works. No file-wide rail or position exclusion is authorized; ranking, pairs, order, conditional, unlisted, focus and Escape checks stay. In `test/enhance-plans.test.ts`, only the one Show-all ordering case may false-by-default omit the real marks it impersonates; it keeps the ordering assertion and separate real marks/plans integration remains.
- **Lifecycle and navigation oracles.** In `test/enhance-lifecycle.test.ts`, only the cleanup-fault case accounts explicitly for restoring the root class when the same injected `removeAttribute` error refused it. It preserves non-empty `AggregateError`, exact error identity, continued cleanup, ownership release, and exact subtree restoration after repairing only deliberately failed attributes and re-enhancing. Only the no-write fold case may use test-only instrumentation of actual `undoAll()` to distinguish forward action from journal undo: it asserts zero all-forward mutation records after destroy before undo, exact subtree and promise ordering, and that removing the fold live check makes the assertion red. No target, type or count filter, feature exclusion, or production hook is authorized. In `test/enhance-nav.test.ts`, only the root-changing-size pin probe tracks each observer identity, callback, observed target and disconnect separately; it proves the pin holds on its own callback, user activity disconnects the pin, the persistent root-width observer remains to destroy, and then all disconnect. Preserve passing root-width integration coverage and require the mutant that deletes pin observation to make the targeted assertion red; a `[root, root]` cardinality patch is not sufficient. The fixture restores the original global descriptor.
- **Source findings remain source work.** The incorrect marks stub header and module-evaluation calls in marks and keysheet are source defects; no scanner or test relaxation is authorized. Folding's chrome-contaminated reading time and empty final section are confirmed production defects, not oracle exceptions. Their source fixes remain separately diagnosed, TDD'd and independently reviewed; correcting a source-only seams oracle does not repair the fold label. This ruling grants no RF3 relaxation, lifecycle or journal source change, golden/corpus/scanner/config change, blanket mock exclusion, target/type/count filter, public API, or whole Task 18/group D acceptance.

## Why

Shared integration made a few synthetic fixtures impersonate owners or reads that are now real, while independent probes distinguish those collisions from source defects.

## Cost if wrong

A narrow fixture repair could hide a regression, so every exclusion is per case and the original real-feature, ordering, cleanup and mutant guarantees remain.
