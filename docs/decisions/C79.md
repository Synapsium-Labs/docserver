# C79: Allow one integration squash while preserving the original feature history

*Recorded 2026-10-26, operator.* · [Decision log](README.md)

## Decision

The operator approved a fresh integration branch from main with the reconciled layout feature squashed into a single-parent commit; the original feature branch and its history remain unchanged. This is the narrow exception to [C55](C55.md) needed because inherited navigation trailers name two snapshots already identical to main, which an ordinary merge cannot remove from the ratchet's reachable history. Preserve the final working changes in a separate local snapshot ref before switching the existing worktree, resolve the measured test-only merge conflict without losing either side, verify the resulting tree against the reconciled inputs, and derive trailers from the actual integration base. No rebase, force-push, ratchet weakening, artificial snapshot changes or new worktree follows. The operator's choice also directs continuation through CI and whole-branch review, not release or publication without their gates.

## Why

Ancestry must not falsely label unchanged snapshots as moved.

## Cost if wrong

An omitted feature delta could be hidden by the squash; tree comparison, fresh tests, the unchanged ratchet and held-out review remain required.
