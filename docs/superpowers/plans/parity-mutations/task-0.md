# Parity Task 0: mutation rows (the free-globals comparison reads names, never alias spellings)

Each row was measured in place on this wave's branch: the bytes of the file saved with their sha256, one edit applied, `test/frame-build.test.ts` run through the fleet test wrapper, then the file restored from the saved bytes and its sha256 compared (equal). The restored hashes: `scripts/build-frame.mjs` `0e4e26f2b80c89eafc253a63145f191e2260649ea133317861a506aef5c82a27` (rows T0a and T0d), `scripts/free-globals.mjs` `844abaf8a4a6393e9fb42e5428daf794163072d80bfaa743ec2eb6b3cfb4b085` (rows T0b and T0c); `test/frame-build.test.ts` stayed `a2667695ea50ebfff957db1ba36f26b70cd892f1a16812d8316257d939ec359a`. The embedding-once check is unchanged by this task, so it has no row. The runs were made under a node heap cap (`env NODE_OPTIONS=--max-old-space-size=1200` between `ccrc test --` and vitest): with the shared test slice holding 3 to 4 GiB for other work, the uncapped file died of the slice's memory cap at its 18th case (the one that spawns a second build), before any assertion. With the cap the file passed 48 of 48 once the slice had room; several runs, capped and uncapped, that died of the memory cap with no assertion mismatch were rerun later, and none of them is counted below.

Why the appended write is the second scan's alone: `globalThis.injected = 1;` appended to the final bootstrap leaves the pinned list as it was (`injected` is allowlisted, so never listed, and `globalThis` is read by another script already), and `freeGlobalList` does not throw on an allowlisted write. The list comparison and the embedding check therefore say nothing; the one problem reported is "the final bootstrap's second scan differs from its first" (the case asserts the free-globals problems are exactly that one). T0b and T0c measure the two parts of that comparison on their own, with the first pass's record changed so that the other part has nothing to see. T0c's record (`writes: ['injected']` beside the unchanged reads) is one no real scan produces, since a name written is always also read; the guard is still red for the right reason. At that checkpoint a pair of real scans was not measured. B1 review fix round 1 re-measured all four guards in focused Node runs. T0c-FR1 compares `globalThis.injected;` to `globalThis.injected = 1;` both as short scripts and appended to the same real bootstrap. In both pairs the reads are equal and only the write changes. The selected control passed all four rows. With the edits restored, the full file passed 49 of 49 under the 1,200 MiB Node heap cap.
