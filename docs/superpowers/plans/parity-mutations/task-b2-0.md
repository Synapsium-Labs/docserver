# Parity Task B2-0: settled-state waits for the plan-marks snapshot and the rail measurements

CI run 44983402840 attempt 1 failed on Node 22 at head 6d6ba96 with two browser failures that had passed on every earlier run of the same code; attempt 2 of the same run, at the unchanged head, passed. Both were measurements taken before the page had settled. WebKit cannot run on the machine that measured these rows: every row below is Chromium only, the Editorial failure itself was not reproduced locally (its shape was), and Classic at 900 px has not yet run in WebKit. CI on the landing's exact tip is the evidence for both.

**Plan-marks snapshot (WebKit, Editorial).** The snapshot caught the scroll spy's first activation (`li .open`, and `a .active` with `aria-current="location"` on the first contents entry) that the expected file lacks. The first work heading sits only about 47 px below the spy's reading line (the larger of 150 px and 30% of the window's height) once the page is settled; on other metrics it can be above the line, so the spy activates, and a later relayout clears it. The alternate layouts' contents rail runs its spy synchronously at build, while the default rail (also used by the review layout) only follows the shared spy, which first runs in the start relayout, queued for the frame after the reader enhances; the harness can return before that frame. One wait now serves every layout and names none: one animation-frame pair passes (so the spy has run at least once), then the page is read until the rail holds no active entry (the wait settles on a neutral rail after the frame pair; its geometry conjunct, the first `h2` at or below the reading line, was dropped in `53f708e` because no mutation isolates it, and the heading's top and the line (from `LINE_MIN` and `LINE_SHARE`, imported from `src/enhance/scroll.ts`) are read only for the message of a wait that times out). A timeout throws with the measured heading top, the line and the active entries. The earlier Classic-only fix (a shorter viewport and a wait) is replaced; the case runs at its own 1440 x 900 window, where the settled heading is below the line in the default and review layouts (370 px and 491 px), Classic and Editorial (317 px each). Classic's case therefore no longer checks the heading against the reading line; its snapshot is unchanged. The frame pair is an ordering precondition of the wait, not a guard: no row can isolate it, and removing it risks the race it serves. No snapshot moved.

**Rail measurement (Chromium).** `source.width` was 348 under the expected `width - 388`, the code block measured as the reading column (704 px at 1440) instead of the wide width (1052 px). The wide width comes from the `long` class, which the code feature first writes in the start relayout (an estimate on a canvas with the system monospace stack, independent of the fonts); that relayout runs in the frame after the reader enhances, and the measurement ran before it. The test now waits for the page to report the root, the rail and the first code block with `long`, before each measurement. `wideMetrics` has the same exposure (a perturbed run reproduces the failure as the same 348 on its 1440 case), so it waits on the same state. Every existing assertion is unchanged. Conjuncts that cannot fire were dropped in the second round: the fonts status is already loaded when the harness returns, `has-toc` is set synchronously at the rail build, the rail reservation and display are static CSS once it is set, an instant scroll cannot leave `scrollY` short of its target, and a frame pair adds nothing once `long` proves a relayout ran.

The plan-marks wait first kept a geometry conjunct (the heading at or below the reading line) beside the neutral-rail conjunct. Measured (row B2R1g), removing it changed no result under the late-shift perturbation or otherwise, because the neutral conjunct and the frame pair already hold the same state; a conjunct no mutation can isolate may not stand, so it was dropped from the wait. The heading's top and the line are still read, for the message of a wait that times out.

Each row edited one file in place; the file's bytes were saved first, restored afterwards, and the sha256 of the restored file checked against the saved one (all pairs match). The plan-marks perturbation moves the first `h2` up 500 px with a transform and sends a resize (so the spy activates), and, where stated, restores it with a resize 1.5 s later. The rail perturbation removes `long` from the block and puts it back 1.5 s later. The spy regression adds one to the index `lastAbove` returns in `src/enhance/scroll.ts` (the active section becomes the one after the last above the line). All runs are Chromium only, through the test wrapper.
