# Parity Task 13: guided layout mutation rows

Every row was measured in place, one at a time, on the guided layout's sources, through the test wrapper, one test file per call, with Chromium selected for browser files. For each file edit the file's bytes were saved first, the edit applied, the test run, and the saved bytes copied back and their SHA-256 checked equal to the one recorded before the edit; no `git checkout` was used. The browser rows read the working stylesheet and bundle sources through the layout harness, so no frame rebuild was needed. Lg-d is a pure judge row: a scratch script (outside the tree) pads the guided bundle's manifest characters in memory and runs `judge` from `test/size-rules.ts`; no runtime asset is padded.

The files moved while the rows were being measured, so each row's JSON records the SHA-256 of the file as that row saw it (`savedSha256`, equal to `restoredSha256`). The stylesheet is at three versions (`5dc30b7f`, then `6025bdcd` once the margin and the print rule were taken out, then `e987536f` once the padding rule was); `layers.ts` is at four (`15865189`; `483c3dc3` once the live check was taken out; `3f4c32fb` once the print handler was added; `70424878` once the field name was a constant of its own file); `sections.ts` is at the version that held the aria-label branch (`6fe843a6`) and a simpler one the rows of Lg2 describe. A guard's text did not change between versions unless its row says so.
