## Second review round: print, measured (rows on 5242485)

The statement that print keeps an 11 pt baseline whatever the size was true for the serif face only: the sans face's rule `[data-font="sans"] { font-size: 17.5px }` sits outside any media query and outranks the print rule, so the sans face prints at its screen size. That is the pre-existing cascade and this wave does not change it (a new print baseline is out of scope). What is claimed now is what T14p measures (Chromium, 1400 px, print media emulated, default layout): for serif and for sans, the printed body size, the h2 size and the column width are the same for every one of s, m, l and xl. Measured: serif 14.6667 px (11 pt), sans 17.5 px, h2 48.8 px and the column 1400 px, at each of the four sizes in both faces. The earlier C7 text and the records that said 11 pt "whatever the size" are corrected to this.
