# LX6.1: the reader ops and in-place reading chrome, mutations

Each row was measured in place, one at a time: the file's bytes were saved and their sha256 taken, the edit applied once, the focused test file(s) run through the box's test wrapper (`./node_modules/.bin/vitest run --maxWorkers=2 <file>`), and the file rewritten from the saved bytes with its sha256 checked equal (every row below restored byte for byte). No row used `git checkout`, `git stash` or `reset --hard`. A C-row (the stylesheet) and a B-row (the bundles) edit a frame asset, so the frame is rebuilt (`node scripts/build-frame.mjs`) after the edit, the browser file is run under Chromium (`DOCREADER_BROWSERS=chromium`; WebKit cannot launch on the measuring box, so no row was measured under it), and `assets/assets.json` and `src/frame/manifest.generated.ts` are rewritten from their saved bytes and the frame rebuilt once more after it.

The control (no edit) is green: `test/reader-ops.test.ts` 22 passed, `test/enhance-reader.test.ts` 22 passed, `test/host-mount.test.ts` 233 passed, `test/reader-ops.test.ts` with `test/frame-seed.test.ts` 215 passed, and `test/browser/frame-reader.test.ts` 7 passed under Chromium (7 skipped under WebKit). Every row is red; the count is the summary of that run, and the first failing case is named.

Three guards were found redundant by a green first measurement and were deleted rather than kept: the `m.size === 2` of the `reading` parser (the key set already refuses another key, and a missing `mode` is no member of the modes), the bar's own `position: fixed` and `transform: none` rules in reader mode (the bar's box is 53 px, so the phone slide moves it 1 px). Two rows were re-measured after their test was strengthened (R33: the root's own sideways scroll needs an overflowing root; R4 named FRAME_ACCEPTS, not the parent ops, in its second measurement).
