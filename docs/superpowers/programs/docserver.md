## Decisions & deviations

- **2026-10-12: the programme (operator).** Each product keeps its own docs server. The rendering is this one library: MIT, pinned by exact version, named `docserver`, scope `@synapsium-labs`. It starts now, and it is private until v1, which goes public. ccrc's spec is approved as written (R-a, R-c, R-f, R-g).
- **2026-10-12: consumers' needs.** ccrc's needs are its spec's §3-§4. Another viewer, which pins the library for its own phase, sent eight needs. They are met by §3.2 as written, and that viewer's coordinator confirmed it the same day. A first release before that viewer's phase is the date that matters. Interim builds are fine for its development.
- **Deviation numbers.** This repo's specs and plans name no allocator-issued numbers, so the ccrc allocator has nothing to seed from. Coordinator rulings are numbered `C<n>`, each with what, why and what it costs if wrong. Each one is a file in the [decision log](../../decisions/README.md), `docs/decisions/C<n>.md`; this ledger keeps the waves, the notes and the checkpoints.
- **2026-10-12: how the L1 plan was made.** Twelve writers each wrote one task against a scratch build of the package, so every code block in the plan is the bytes of a commit that passed its own tests. A three-lens review (spec, safety, tests) then found 24 issues, four of them blockers: inputs that made rendering slow or used too much memory. All four are fixed inside the tasks that own them, and the plan's former Task 13 was folded into those tasks. A final pass applied C19-C23, and a verifier checked it.

## Carried constraints (reviewers get these)

- Public-ready text from the first commit (`CLAUDE.md`): no hosts, users, private paths, project lists, issue-tracker workspaces, private product names or operator defaults.
- Pure library: no network, storage backend, auth, git or hosting.
- One raw-HTML allowlist, identical in Node and the browser.
- Browser code is CSP-safe: no `innerHTML`, `eval` or inline handlers.
- The corpus is the contract: a golden change is stated, and a hostile verdict never weakens.

1. **The plan** is written prototype-first, as L2's was (C40): [`2026-10-26-docserver-l3-frame-and-release.md`](../plans/2026-10-26-docserver-l3-frame-and-release.md), on draft #41 with the prototype until the operator's review. The plan goes to the operator for review before it runs (spec, "Where things stand").
2. **The frame contract** is the first consumer's reader-frame contract seen from the library. The CSP meta comes first, then the click guard, the seed and the bootstrap, in that order, before any content. The bootstrap reads the seed as the element just before its own script, never by id. The seed escapes `<`, U+2028 and U+2029. `hello` is accepted once, on the first load, with exactly one port, and `ready` echoes the seed's nonce. `BRIDGE_PROTOCOL` starts at 1.
3. **The first consumer's three requests** (spec §8: a `./highlight` subpath, `render()` with `highlight: false`, and a hostile xml `<script>`/`<style>` case) may ride v1. None blocks it.
4. **v1** makes the repository public and publishes `@synapsium-labs/docserver` (C84). Both are outward and hard to reverse, so each waits for the operator's explicit go at that step, after a private-name scan of the full history and the repository's GitHub text (Task 15).

**Waiting on the operator.** Nothing blocks execution (C85). The plan's defaults (Q1 to Q4, Q6 to Q8, Q10 to Q13, S1 to S4 and the two Mermaid builds, Q12) stay open to the operator's review. At release: Q5 (a placeholder publish, if npm needs one before a trusted publisher can be attached), Q9 (who holds the tag-signing key), and the explicit go for each outward step of Task 15.
