## Departures and readings

- **ccrc D-8881 (shared folds).** Guided keeps its layers in the existing `folds` field and its choice of layers in the UI memory, not in per-layout document fields as the design's section 6 and the plan's per-layout contract say, because of the bootstrap budget (32,740 of 32,768 bytes, 28 left): a field of its own raises it. Effect: a fold or layer set in one layout shows in the other for the same document, where the other has a section for it. Both layouts read the other's value safely (rows Lg5-f and Lg5-g in the Task 13 record: a value that is not a list, a non-string entry or an id with no section is ignored, never thrown on and never rewritten by a read). Three limits, as ruled (ccrc D-8881): (1) a document with nothing folded reads as unvisited: the default layout deletes the field when nothing is folded, so guided applies its own first-visit layers next time (all folded for a long document unless the reader chose full, or when its layers choice is guided); (2) the default layout's own fold write (a fold, a reveal or `beforematch`) keeps only its own entries, so it drops entries only guided has, while guided's write keeps the entries it does not own (ccrc D-8881), and "never rewritten" means never by a read; (3) guided's reader-wide layers choice lives in the existing UI preference (`pref:ui`, key `layers`), covered by ccrc D-8881, and adds no field. The review layout adds no state of its own, so the per-layout-state row reads true for it (the first line of the Task 12 record). The effect is stated in the guided audit, the plan's B2 departures, here, and the pull request description.
- **Feature selections, not ports.** Review and guided select shared modules and add their own; neither is pixel or complete behavioural parity with the reference.
