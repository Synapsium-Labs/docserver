# Reader mode, library landing (LX6.1 to LX6.3): notes for the ledger

What the programme ledger should learn from this landing, for the coordinator to fold in. The plan's tasks are LX6.1 to LX6.3 of the native docs reader-mode plan; the mutation records are [`lx6-mutations/task-1.md`](../../plans/lx6-mutations/task-1.md), [`task-2.md`](../../plans/lx6-mutations/task-2.md) and [`task-3.md`](../../plans/lx6-mutations/task-3.md).

- **Scope.** One pull request from `main` at `6882c79` (the X6 share reservation): the `reading` (host to frame) and `reader` (frame to host) ops with their pacing constants, the opt-in `bridge.reader` seed flag set by `HostAdapters.onReader`, `DocFrame.setReading`, the in-place reading chrome with `r` and Esc; screen pages (`src/enhance/pages.ts`: turns by tap, swipe and keys in `screens` mode only, the top band's `menu`, the pinned-head offset, the ground band, the re-snap after a resize, a width or a text-size change); the text size `s | m | l | xl` in enhance's own stored prefs with an Aa row (screen only, print keeps its 11 pt); `render()`'s `meta.readingMinutes`. No version bump, tag, publication, workflow, repository setting or consumer edit; the large-document gate, thresholds, old budgets, the share table and the earlier growth rows are unchanged.
- **Size.** One new `x6` growth row, `{"design":"x6","total":5316225,"frame":4580056}`. Against `main`: total +36 745 of the 59 392 share (22 647 left), frame +8 631 of 15 360 (6 729 left). The new enhance modules are shared, so each of the five layout bundles carries them. `reader.css` grew 1 648 characters. The bootstrap is 32 681 of its 32 768 bytes (87 left): 32 740 before, 31 992 with the behaviour-neutral byte saving alone (a module-local `Object.freeze` alias), 32 681 with the new ops. `ASSET_BUDGETS` are unchanged.
- **Deviations.**
  - D-8950: `DocFrame.setReading` carries the mode to a later remount by posting it when the new mount is `ready`, not in the seed (the plan says it "seeds a later remount"). Why: bootstrap bytes (87 left). Cost: a remount shows the full reading chrome until `ready` unless the host plans the chrome at mount; the host's next wave should pass `features.chrome` at a reader-mode remount. The README says so.
  - D-8951: the text size's `m` is the reader's existing body size, so the sans face reads 17.5 px and a phone 17 px at `m`, not 18 (the plan names 16, 18, 20 and 22 px). Why: `m` keeps today's look byte for byte, and a half-pixel sans offset per size costs stylesheet characters. The README says so.
- **Rulings (no deviation number).**
  - The settings-menu layout snapshot (`conformance/layout/settings/menu.dom.txt`) moved: the Aa row is the task's own change to that menu, so it is not an unrelated snapshot. The commit names it on its `Layout-moved:` line. No golden moved; `readingMinutes` is left out of golden meta as an empty `items` is.
  - The reading-time rule lives in two copies, enhance's byline and the renderer's print facts, because the repository's import walls keep `src/enhance` and `src/render` apart. `test/reading-minutes.test.ts` proves they agree on every corpus document with a file input and at rounding edges. `meta.readingMinutes` is the unrounded figure the byline rounds, as a time-left display needs.
  - Two guards that measured green under mutation were deleted rather than kept untested: the `keyboard` check on the Escape path in `keys.ts` and a `root.contains` check in the sideways-scroll walk in `pages.ts`.
- **Measurement.** Local runs are Chromium only: WebKit cannot launch on the worker box, so no case ran in WebKit locally; hosted CI runs both engines. The full Chromium suite at the final code tip ran with some files' workers killed by the test slice's memory cap; each killed file was re-run alone and passed. `test/size-contract.test.ts` passes with the base `origin/main` and the text `Size-Design: x6`. The package-consumer check (`test/pack.test.ts`) passes 15 of 15.
